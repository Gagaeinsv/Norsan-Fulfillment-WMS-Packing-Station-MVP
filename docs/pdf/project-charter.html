Project Charter

Norsan & ZREEN – Fulfillment WMS: Postazione di Imballaggio Rapido 1-Scan
Hub di Bolzano · Versione 2.0 · Stato: Fase 1 + Nucleo Multi-Banco Completati (Pronto per API DHL / Selly)

1. Sintesi del progetto

Il progetto introduce una postazione di imballaggio ad alta velocità per l'hub logistico di Bolzano, ottimizzata secondo le indicazioni operative della direzione: 1 sola scansione della bolla per aprire l'ordine, bloccarlo atomicamente sul banco (impedendo doppie lavorazioni su altri tavoli) e stampare subito l'etichetta termica DHL, senza rallentare l'operatore con scansioni obbligatorie dei singoli flaconi.

Obiettivo di business: velocizzare l'evasione al banco eliminando ricerche manuali e doppie spedizioni su 2+ tavoli, ridurre gli errori di indirizzo e di imballaggio grazie alla guida visuale 5S e rendere il reparto misurabile (UPH, ordini evasi, coda Kanban) sostituendo costosi middleware esterni.

2. Business Case

Problema attualeRicerca manuale degli ordini su gestionali esterni, nessuna protezione contro il doppio imballaggio della stessa bolla su 2 banchi, indirizzi italiani bloccati dal corriere per campi non separati, alta curva di apprendimento per nuovo personale e assenza di dati sul ritmo di reparto.
Soluzione propostaApplicazione web Swiss-Light Industrial con flusso 1-Scan Bolla → Lock Multi-Banco → Stampa DHL immediata, guida visuale a 5 piani per tavoli speculari NORSAN/ZREEN, gestione scatola neutra Amazon FBM, parser indirizzi italiani, coda api_outbox e Dashboard Control Tower per il Team Lead.
Benefici attesi
  • Velocità operativa: 1 scansione sulla bolla genera subito la stampa DHL senza scansioni intermedie obbligatorie per ogni singolo flacone.
  • Zero doppie spedizioni: il lock atomico SQLite blocca duplicati su altri tavoli (409 Conflict) e consente al Team Lead lo sblocco rapido (Force Release).
  • Onboarding immediato: foto prodotto, lato scaffale speculare (ST-01/ST-02), formato scatola e promemoria volantini/omaggi riducono gli errori fin dal primo giorno.
  • Indipendenza da middleware a pagamento: flusso Amazon FBM, Selly ERP e corriere gestiti internamente senza canoni esterni ricorrenti.
Alternative considerateMantenere il processo manuale senza blocco ordini né guida visuale, oppure acquistare un WMS commerciale generico (costi elevati, licenze per postazione, rigido rispetto ai banchi speculari Norsan/ZREEN).

6. Analisi SWOT

Punti di forza

  • Flusso 1-Scan veloce approvato per la produzione
  • Order Locking anti-duplicati pronto nel nucleo SQLite
  • 29 test automatici attivi e architettura pronta per Docker/API

Debolezze

  • Etichetta DHL ancora simulata in attesa di API Key
  • Sincronizzazione Selly via CSV finché non arrivano le chiavi REST
  • Moduli FEFO/magazzino congelati in attesa validazione dati reali

Opportunità

  • Eliminazione middleware esterni e lavoro manuale di copia/incolla
  • Riduzione errori su scatole Amazon e indirizzi italiani DHL
  • Estensione graduale verso Cutoff SLA, Resi RMA e tracciabilità HACCP

Minacce

  • Ritardo nella fornitura credenziali API da partner/direzione
  • Mixed Content se frontend HTTPS punta a server LAN non HTTPS
  • Mancata allocazione ore dedicate per completare le integrazioni

9. Requisiti per il Go-Live con API (Fase 2)

  • Allocazione formale ore: conferma monte ore settimanale dedicato al Project Manager / PO per completamento connettori e rilascio in reparto.
  • Credenziali tecniche in .env: chiavi sandbox/produzione per DHL Business API (o aggregatore spedizioni), Selly ERP API ed eventualmente Amazon SP-API.
  • Catalogo & Regole Selly ERP: export completo SKU foten (con volantino dedicato e nessuna scatola brandizzata) e verifica della regola di raggruppamento ordini consolidati (Progressivo ordine cliente 1, 2...) per spedizioni multi-sito in 1 sola scatola/etichetta.
  • Infrastruttura condivisa: attivazione di un host Docker/Node in rete locale Bolzano oppure VPS con disco persistente per condividere code ordini e lock tra tutti i banchi.
